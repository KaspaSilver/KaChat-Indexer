# Indexer audit, 2026-11-25

**Scope:** `f2e67b4..ca785ff` (53 commits since the last kachat-audits run, run 23), then the
surrounding code. Components: push service, chat indexer, K transaction processor, webserver,
admin, profiles follower. The live stack was checked read-only (logs, ports, schema).

**Method:** four parallel read-only reviews. Every finding fixed here was re-read in the code
first. Open items marked *(reported)* were not re-verified line by line in this session.

## Open

### Chat indexer
- **P1, live:** a sender lookup that fails with anything but a disconnect is never retried
  (`indexer-actors/src/data_source.rs`, `RequestSender` arm).
  - The record keeps an unknown sender, and its push never fires until the next restart.
  - Live, this happens about 10 times in 30 minutes, and 18 times in the 24 hours before.
  - Likely part of the "delayed notifications" report.
  - Fix: retry with backoff, and drop it only after N tries.
- **P2** *(reported)*: `/personal/purge-sender` can leave zero-sender receiver rows whose payload
  it deleted, so whole handshake or group pages answer 500. Fix: also delete by tx id, and make
  those read paths skip a missing payload.
- **P2** *(reported)*: a blocked sender's record can come back when another block holding the
  same tx arrives after the sender resolved; that entry is never resolved.
- **P2** *(reported)*: one tx can get two acceptance records (different receiver), and the
  `key_by_tx_id` assert then kills a processor thread on every restart. There is no watchdog.
- **P2** *(reported)*: watched outpoints that are never spent are never pruned. Coinbase outputs
  are written at sighting, and every merging block has one. Anyone can add watch-only
  addresses.
- **P2** *(reported)*: `/personal/purge-all` plus a pending group-message resolution makes the
  virtual chain processor exit, on every restart.
- **P2** *(reported, older code)*: with an unknown sender and change-first outputs, a payment or
  handshake is filed under the sender, not the receiver.
- **P3** *(reported)*: `/import-file` restores purged rows and accepts wrong-length keys, which
  later panic.

### Push service
- **P2:** primary addresses stored before the signer-binding fix (10715be) are never
  re-checked.
- **P2:** an unauthenticated watch-only registration makes the single registry thread run full
  scans. There is no cap on registrations and no rate limit.
- **P3:** anyone can register another user's `kaposts_pubkey` and receive their KaPost
  notifications. The field is not tied to the signer.

### K processor
- **P2:** the signature is claimed before the tx checks, so a zero-pay front-run copy burns a
  real tip.
- **P2:** admin-deleted posts and room messages come back on restart catch-up or a reindex.
  There is no moderation tombstone.
- **P2:** unvote has no ordering guard, so parallel workers or a reindex can leave the wrong
  vote.
- **P2:** no push throttle for room @mentions or follow/like cycling, and `/names/{name}` lookups
  are uncached.
- **P2:** after an outage, the ingester's backlog pushes as if live.
- **P2:** poll votes and follows are still unique by raw key, so the same key in its three valid
  forms (`02x`, `03x`, `x`) counts three times.
- **P3:** at startup, catch-up runs before the first switch, denylist and blocklist load.
- **P3:** anything posted to the KaPlay rooms is kept forever, unvalidated (up to 1 MB a row).
- **P3:** the retry path pushes outside quiet mode; a vote's notification target isn't checked
  against the post author.
- **P3, live:** "Unknown K protocol action 'comm' / 'gcomm' / 'profile' / 'name'" is logged as a
  warning for every chat transaction.

### Webserver and admin
- **P2:** the arcade and chess-bot boards replay all history every 30 s on the async runtime,
  with no single-flight. Cheap spam rows could stall the webserver.
- **P2:** `/api/settings` returns early when `supervisorctl` fails, and drops the fields after it
  in the same request.
- **P3:** `/broadcast-channels` lists the hidden KaPlay rooms and ignores `feature_kaplay`.
- **P3:** `/identity` on the names server ignores the address's network prefix.
- **P3:** admin chat-import puts an unchecked address into the explorer URL path
  (admin-token only).
- **P3:** the blocklist purge leaves `k_polls` and `post_translations` rows of purged posts.
